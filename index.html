How it works

Requests come to the key.
The key never goes to them.

Most key managers hand the raw key to whoever asks. GhostKey delegates revocable access instead — ideally a proxied call where the key stays encrypted in the vault the whole time.

01

Store once, encrypted

Paste a key and it's sealed with AES-256-GCM, derived from your passphrase. Nothing syncs, nothing phones home.

02

Apps ask, you approve

Every request names who's asking and for which provider. Allow it once, for a session, or always — and revoke anytime.

03

The key stays home

GhostKey makes the call and returns the response. Requesters get answers, never the key — unless you explicitly reveal it.

What's inside

Everything a key vault should be.

Encrypted vault

AES-256-GCM with 600,000-round PBKDF2 key derivation, entirely via Web Crypto. Add, edit, rotate, export.

Proxy by default

GhostKey forwards the request and injects the key server-side. The requester sees the response, never the secret.

Short-lived sessions

Grants expire and auto-revoke. "Allow once" lasts two minutes; sessions default to thirty. Nothing is forever.

Full audit log

Every grant, deny, and proxied call is recorded on-device with requester, provider, and status — no secrets stored.

Spend caps + kill-switch

Estimated cost per provider, a hard monthly cap, and a one-click switch that refuses all access instantly.

Security model

Auditable by design. No build step to hide behind.

All the crypto lives in one small, unminified file. What you load is exactly what runs.

  • AES-256-GCMAuthenticated encryption — tampering and wrong passphrases are rejected, not silently mangled.
  • PBKDF2 ×600kHMAC-SHA-256 with a random per-vault salt makes brute-forcing your passphrase expensive.
  • non-extractableThe derived key lives only in the service worker's memory while unlocked, and can't be exported.
  • fresh IV / writeA new 96-bit nonce every time — nonce reuse, the classic GCM footgun, can't happen.

FAQ

Questions, answered.

Where are my API keys stored?

Only on your device, encrypted, in the browser's extension storage. There are no GhostKey servers, accounts, or telemetry — nothing is uploaded anywhere.

How are the keys protected?

Each key is encrypted with AES-256-GCM. The encryption key is derived from your master passphrase using PBKDF2-HMAC-SHA-256 with 600,000 iterations, and it exists only in memory while the vault is unlocked.

What happens if I forget my passphrase?

It can't be recovered — that's the point. Your passphrase is never stored or transmitted, so choose something strong you'll remember, and keep an encrypted backup export somewhere safe.

Can any app use my keys?

Only apps you explicitly approve, and only for as long as you allow. By default GhostKey proxies the request so the app receives the response but never the raw key. You can revoke any grant instantly.

Which providers are supported?

OpenAI, Anthropic, Google Gemini, xAI, OpenRouter, Groq, DeepSeek, Mistral, Qwen, Moonshot Kimi, Ollama, and LM Studio — plus any OpenAI-compatible endpoint you configure.

Does it cost anything?

No. GhostKey is free and open source under the MIT license. You only pay your AI providers for the tokens you use — and GhostKey shows you an estimate.
